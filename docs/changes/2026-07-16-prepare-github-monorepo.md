# 整理 SmartCar 2026 工作区并准备 GitHub 首次发布

## 目的

将当前实车和仿真工作区整理为可维护的私有 GitHub 单仓库，同时避免上传本地备份、超限模型权重、构建产物、设备凭据和厂商二进制文件。

## 涉及文件

- 新增根目录 `README.md`，说明工作区结构、环境、运行入口和分发边界。
- 新增根目录 `.gitignore`，排除备份、归档、ROS/Python 构建产物、模型权重、二进制、生成媒体、本机凭据和误提取的 Windows 文件。
- 更新 `ucar_ws/src/.gitignore`，取消其仅为旧嵌套仓库保留的全目录忽略规则，使实车 Catkin 包源码可由根仓库统一管理。
- 更新 `docs/operations.md`，加入首次初始化、私有仓库发布与后续同步命令。

## 验证结果

- 已审查工作区：`ucar_ws_source.tar.gz` 为约 1.54 GB 归档，三个 YOLO 权重文件均超过 GitHub 的 100 MB 单文件限制，均由忽略规则排除。
- 根仓库暂存 2,375 个文件、约 177.33 MB，最大单个 blob 为 15.26 MB；不存在超过 95 MB 的待上传文件。
- 已检查嵌套 Git 元数据：它们已完整复位到本机原路径，根仓库暂存区不含 Git 子模块或历史元数据。
- 已通过根目录说明、操作文档和忽略规则的空白检查；全量导入的历史源码存在尾随空白，未作无关格式化。
- 已执行凭据标记扫描：命中仅位于第三方 CI 配置和 jQuery 文档，未发现待提交的本机 App ID、权重或归档文件。
- GitHub CLI 已登录并具备创建私有仓库和推送所需的权限。
- 首次提交、远程仓库创建和推送使用 `docs/operations.md` 中记录的命令执行。

## 已知限制

- 克隆仓库后，需从授权来源补充模型权重和厂商运行时资源，并重新配置设备 App ID。
- 本机是 Windows 工作目录，未在本次整理中执行 ROS 构建；应在对应的 Ubuntu/ROS 环境按操作文档验证。
- 导入的历史源码存在尾随空白；本次未进行无关格式化，以避免将首次发布与功能变更混在一起。
