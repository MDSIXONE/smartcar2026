### 2026-07-29：ROS 相机退出后的 V4L2 暂态失败没有重试

- **现象**：完整任务安全到达 52 并识别三个不同二维码，释放 `/usb_cam` 后启动 Python 3 OCR helper；OpenCV 连续两次报告像素格式不支持和设备忙，helper 立即退出，任务以 `ABORTED` 停车，未进入生产路线。
- **原因**：原 `open_camera()` 只做 V4L2 和默认 backend 两次紧邻尝试，没有覆盖 ROS 节点退出、V4L2 stream-off 和设备重新协商之间的短暂交接窗口；OCR 模型与 `/dev/ucar_video` 软链接、设备支持的 YUYV/MJPG 格式均正常。
- **修复**：增加由 `camera_open_timeout` 约束的多次打开/预热重试，并明确请求 YUYV；新增 Python 3 fake-camera 回归测试，先确认旧实现因第三次才能成功而失败，再确认修复通过。车端构建、原有 15 项测试、新增 1 项测试和真实 `usb_cam` 释放后 0.1 秒切换均通过。
- **预防**：独占硬件从一个进程交接到另一个进程时不能把 `rosnode kill` 返回等同于设备已稳定；打开、格式协商和首帧都要有短周期有界重试，最终超时仍必须零速终止。

### 2026-07-29：车辆离开起点后重启固定初值定位链路

- **现象**：首次任务在 52 因相机交接失败并停止完整 launch；未先把车放回起点就重启 mission。`lidar_loc` 再次采用 `(-0.25, 2.75, 0)` 固定初值，而实车位于 52，`map -> base_link` 与实际位置不一致，任务开始向 52 发送错误定位下的导航运动。

- **修复**：发现地图位姿与已知实车位置不符后立即发布零速度并停止完整链路；等待人工把车放回起点后才允许重启。操作文档新增中途终止后的重启门禁。
- **预防**：安全门除有限值和新鲜度外，还必须核对启动时实车已知位置与 `map -> base_link` 初值一致；固定初值定位方案下，任何离开起点后的整链重启都要求先物理复位或提供经过验证的当前初值。

- **现象**：车端编译与纯函数测试全部通过，但 Sol 最终复核发现：活动横移会在前视阻挡临时消失时提前清空状态；footprint 扫描遇第一个阻挡格就返回，不能判断接触是否变多；横移预览只看全局 OccupancyGrid，没有把本地动态障碍纳入决策。
- **原因**：测试只覆盖方向、布尔判据和预算纯函数，没有覆盖 `computeVelocityCommands` 的跨周期状态、完整多格 polygon 或全局/本地代价地图组合，形成了关键路径假覆盖。
- **修复**：把预防置于优先，拆分两模式参数并降低 `mode2_body_projection` 默认速度；新增 `escape_enabled`，YAML 设为 `false`，源码硬制为关闭并拒绝任何 `true` 请求，使三个 P1 路径当前不可达。
- **预防**：任何会输出非零恢复速度的功能，必须建立跨周期本地规划器集成测试、全 polygon 接触计数测试和本地动态障碍测试；纯方向单测不能作为实车启用依据。

### 2026-07-29：拆分低速参数后仍遗漏正常控制的近车盲区和 NaN

- **现象**：第二轮 Sol 复核确认脱困已关闭、两模式参数已分离，但发现正常碰撞检查从约 20 cm 前的 `target_index_` 开始，跳过当前车体到目标索引之间；同时 NaN 进入原 `clampValue` 的 `std::min/std::max` 组合可能产生负最大角速度。
- **原因**：把“降低速度”误当成完整预防，没有按实际候选 Twist 检查矩形车体的旋转扫掠；限幅函数也没有实现非有限值失败关闭。
- **修复**：路径检查改为先检查当前真实车体，再从全局路径离当前车体最近的点开始；模式 2 对实际 Twist 每 0.025 s 投影未来 0.40 s，同时检查全局和本地代价地图；位姿、误差、周期和最终 Twist 任一非有限都保持零速并返回失败，限幅函数对非有限输入返回零。
- **预防**：运动参数调整后的复核必须覆盖“当前车体到前视点”的完整区间和实际 `(v,w)` 扫掠；所有浮点控制链在限幅之前都要有显式 finite 门禁。

### 2026-07-29：组合校验命令再次被引号和超时破坏

- **现象**：一次本地哈希/YAML 组合检查触发 PowerShell ParserError；随后一次远端 Python YAML 检查因多层引号使文件路径被拆开，报 `IOError`。最终收尾又把整份档案读取、多个搜索和 `git diff --check` 合在一个 10 秒命令中，虽已输出关键结果仍以超时 124 结束。
- **原因**：把 PowerShell、SSH、Python 字符串和含路径的表达式继续嵌套在一条命令中，又把多个成功条件不同的只读检查放进同一个短超时调用，没有遵循既有的短命令规则。
- **修复**：没有依据失败输出修改代码或远端文件；改为分别执行哈希、YAML、进程和 diff 检查，并通过标准输入把 YAML 内容传给远端 Python 解析，避免远端文件路径和 Python 字符串嵌套。
- **预防**：PowerShell 到 SSH 的校验命令保持单一职责；结构化文件优先经标准输入解析，禁止在三层 Shell 中拼接带引号的路径和复合表达式；整份档案读取不得与仓库级 diff 检查共用超时和退出码。

### 2026-07-29：性能优化勘察再次组合超时并误用跨 Shell 替换

- **现象**：一次把 launch、任务脚本、规划器源码和多个配置合并读取的命令在 20 秒超时；一次查询车端 `usb_cam` 时在 PowerShell 双引号内写了远端 `$(rospack find usb_cam)`，被本机提前解释；还按不存在的状态机测试文件名和 PowerShell 不支持的 `*.py` LiteralPath 查找，产生路径错误。一次并行红灯检查因其中一项预期失败而只返回一个结果。收尾时两次尝试删除本地 `__pycache__` 被安全策略拒绝；一次组合验证中远端 YAML Python 字符串被 SSH 引号破坏，测试与 launch 解析已经成功却使整条命令退出 1；第一次改用标准输入时又把 `YAML_OK` 的字符串引号丢失成变量名。最后为查一个 Costmap2D 运算符又对车端多个大目录递归 `grep`，在 24 秒超时。

- **修复**：所有失败均为只读、被策略拦截或预期红灯，没有启动 ROS、修改远端运行状态或依据不完整输出做结论；生成缓存未被纳入改动。随后使用显式 `/home/ucar/ucar_ws/src/usb_cam` 路径、`rg --files` 和独立命令重新核验；C++ 与 Python 红灯分别得到预期的缺失 helper/方法错误；4 份 YAML 改为分别从标准输入解析，并只输出数字，全部通过；Costmap2D 声明改为只读取已知头文件。
- **预防**：大型源码勘察按文件和函数拆分；PowerShell 到 SSH 禁用 `$()`；未知测试路径先 `rg --files`；预期失败的 TDD 命令用独立调用或 `Promise.allSettled`，避免一个红灯遮住另一个结果；不为收尾验证清理无关缓存；结构化文件验证禁止在三层 Shell 中嵌套路径或字符串引号；已知系统头文件位置时禁止从 `/opt/ros` 和整个工作区做无界递归搜索。

### 2026-07-29：构建后静态 launch 检查漏加载工作区环境
