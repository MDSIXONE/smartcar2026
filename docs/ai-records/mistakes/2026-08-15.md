# 2026-08-15

### 2026-08-15：常驻交接 include 漏传 is_fork:=yolo，交接点黄线被当终点横线，巡线全程跳过

- **现象**：主流程在 441 交接给常驻 lane_proto 后，激活 2.8 秒即
  `== APPROACH == 打点完成`，前进 0.5m 后 `STOPPED` 并播报"任务完成"，
  主流程报 `PRODUCTION_LANE_HANDOFF_COMPLETED`。黄线对齐、认灯、进三岔口、
  巡线整段被跳过；车在黄线前就到"终点"。
- **原因**：8-14 把终点巡线从"退出主 launch + handoff_lane.sh 独立重启"改为
  "常驻 lane_proto + set_active 交接"时，参数平移到 `2026.launch` include 时
  **遗漏 `is_fork:=yolo`**（及 template/align_offset/start_offset/goal_y_lo/
  linear_speed/rate 等整套起跑参数）。`is_fork` 缺省 false → 起跑序列不走，
  交接后 `FOLLOW` 相位直接认横线；交接点画面里那条黄线（441 面向 170 的设计
  就是为了看到它）被 `goal_block` 检中，`goal_confirm=1` 一帧命中即触发终点流程。
  与 TrackSeg 延迟加载无直接因果，但同批部署、只在现场首次交接暴露。
- **修复**：`2026.launch` 常驻 include 补齐 `is_fork:=yolo` 及
  handoff_lane.sh（2026-08-12 最终值）整套参数，`goal_pause` 恢复 1.0；
  lane_proto 回归新增 `test_resident_handoff_keeps_start_sequence_parameters`
  锁住 include 参数完整性。
- **预防**：把"脚本固定参数启动"迁移为"launch include 常驻"时必须逐参数
  diff 两处参数表，并为关键参数（is_fork/template）加结构回归测试；交接类
  改动不能只靠语法/静态回归，必须现场观察首个相位（本次应为 ALIGN 而非
  APPROACH）才算验证。
