### 2026-08-12：WSL p9_client_rpc 阻塞 Noetic catkin_make

- **现象**：仿真部署副本 `/home/car/smartcar2026-simulation` 执行 `catkin_make -j2` 时，
  `cmake_check_build_system` 中的 CMake 长时间无输出、CPU 为 0，进程状态为 D，`wchan` 为
  `p9_client_rpc`。
- **原因**：WSL 文件系统的 9P 调用未返回；bridge 的 Python 3 `--help` 与 `py_compile` 均已通过，
  因而不是 bridge 语法、ROS 环境或 Gazebo 进程问题。
- **修复**：只向本次构建 shell 发送 SIGINT，随即确认 catkin/CMake 子进程退出，且无
  roslaunch、roscore、Gazebo 或 bridge 残留；保留 WSL-only `Testing/` 资产并登记到
  `.git/info/exclude`。
- **预防**：构建卡住先查 `ps`/`wchan`，识别 `p9_client_rpc` 后不要并发重跑或删除 build/资产；
  待 WSL 文件系统恢复后在干净终端重跑构建。

### pgrep 命令行模式自匹配

- **现象**：用 pgrep -af 检查 sim_bridge.py 是否残留运行时，检查命令自身被报告为匹配项。
- **原因**：模式文本出现在正在执行的 ash -lc 命令行中。
- **修复**：改用匹配实际 Python 进程起始命令的 pgrep -f '^python3 /home/car/simulation_bridge/sim_bridge.py'。
- **预防**：检查命令行模式时，匹配实际目标命令的稳定起始部分，避免把待匹配字面量放入检查 shell 本身的命令行。
