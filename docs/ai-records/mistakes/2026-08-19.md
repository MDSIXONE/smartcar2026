# 2026-08-19

### 备用导航超时变量提前读取破坏同点快捷路径

- **现象**：车端 ROS 回归中，同点 QR 旋转测试因测试夹具没有 `goal_timeout` 属性而报错。
- **原因**：新增备用导航超时变量在 `navigate_coordinates()` 的同点原地旋转快捷判断之前读取；该路径本来不需要 move_base 超时。
- **修复**：将超时变量计算移动到同点快捷返回和全局规划等待之后，仅实际发送 move_base 目标时读取。
- **预防**：新增导航参数不能改变不依赖该参数的快捷路径；测试应覆盖同点旋转和普通导航两条分支。
- **相关改动**：2026-08-19 目标守卫备用点导航失败切换。

### 目标守卫备用点只检查障碍命中、不检查导航结果

- **现象**：目标 11 的守卫点 419 命中后选择备用点 428；全局规划有结果，但 CymPlanner 报前方阻挡，任务仍等待完整 `180s`，没有尝试 446/448。
- **原因**：备用候选只按守卫扫描结果过滤，没有把局部规划失败作为候选失败；备用导航复用了普通目标的超时和中止语义，`MissionAbort` 直接终止候选循环。
- **修复**：备用导航使用独立 `25s` 超时；失败返回 `target_navigation_failed` 并切换下一个候选；普通目标仍失败即中止。
- **预防**：目标守卫的“扫描可用”与“导航可达”必须分别验收；备用点不能复用全局任务超时，也不能把候选失败直接升级成任务级中止。
- **相关改动**：2026-08-19 目标守卫备用点导航失败切换。

### PowerShell 嵌套 SSH 命令改写 Python2 校验代码

- **现象**：通过 PowerShell 执行包含 `ssh ... "python2 -c ..."` 的远端解析命令时，车端收到的 Python 代码被截断并报 `IndentationError`；文件上传和 SHA-256 校验不受影响。
- **原因**：PowerShell、SSH 远端 shell、Python `-c` 三层引号同时解析，反斜杠转义没有按预期传递。
- **处理**：将 Python2 AST 和 launch XML 校验拆成两个使用单引号包裹远端命令的 SSH 只读命令，均通过。
- **预防**：车端复杂 Python 校验优先拆分命令或使用 Base64 脚本传输，避免多层 shell 引号嵌套。

### 2026-08-19：锥桶遮挡远处 OCR 小框触发重复对准

- **现象**：点 11 识别到远处“电子产品生产车间”后，OCR 对准 6 次都未进入容差；候选被拒绝后继续 360° 扫描，再次识别同一标签并重复对准。
- **原因**：候选入口只检查文字和置信度，没有检查 OCR bbox 的可见面积；锥桶遮挡时远处/残缺框仍能进入停车与对准链路。对准失败又不会标记当前小框已处理。
- **修复**：三套主流程在候选进入对准前增加 `bbox_width × bbox_height >= 6 × alignment_tolerance_px²` 面积门；当前 `20px` 容差对应 `2400px²`，小框直接丢弃并记录原因。
- **预防**：视觉候选不仅要看置信度，还要检查可见尺寸；尺寸门槛必须用现场有效框样本校准，不能直接用 `3×容差` 的单边宽度，否则会过滤本次约 `51×38px` 的有效框。
- **相关改动**：`2026-08-19-ocr-small-box-filter.md`。

### 2026-08-19：省赛参数同步后测试仍锁定旧模板

- **现象**：省赛巡线参数按用户要求从 `red_template_band2.png` 同步为 `red_template_band.png` 后，lane_proto 回归仍因旧模板断言失败。
- **原因**：测试把现场可调参数的历史值当成了永久契约，没有随启动配置同步更新。
- **修复**：将省赛测试断言改为当前明确配置；三态入口、国赛定点和省赛自读雷达参数均重新锁定。
- **预防**：参数同步时区分“行为不变量”和“当前现场值”；可调参数变化必须同时更新对应 launch、操作文档和配置回归。

### 2026-08-19：QR 同点负角度切换未锁定最短转向

- **现象**：QR 旋转扫描从 `-90°` 切换到 `-135°` 时，车辆逆时针绕行一大圈。
- **原因**：同点朝向目标直接交给 `move_base`，任务层没有显式计算目标角与当前角的最短有符号角差，也没有按 odom 累计实际转向进度。
- **修复**：三套主流程对无规划且同点的朝向目标改用 odom 闭环；先归一化 `target-current`，再按符号发布原地角速度并验收实际进度。
- **预防**：固定朝向同点旋转必须显式锁定最短角差并验证有符号 odom 进度，不能从目标角标签推断规划器一定会选择短弧。

### 2026-08-19：直接 roslaunch 未带车端 Master 生命周期

- **现象**：停止旧任务后直接后台启动 `roslaunch`，进程存在但没有子节点；`rosnode list` 报 `Unable to communicate with master`。
- **原因**：车端正式入口 `start_2026.sh` 负责计算 `ROS_MASTER_URI`、启动本机 `roscore`、再启动 `roslaunch`；直接启动没有恢复 Master 和对应环境。
- **预防**：实车重启必须使用 `start_2026.sh <PC_IP> manual|mission`，启动后先检查 Master、`rosnode list` 和关键节点；不要只看 roslaunch PID。
- **相关改动**：`2026-08-19-navigation-arrival-retry-continue.md`。

### 2026-08-19：三套生产任务依赖模块未整包同步

- **现象**：车端 `ucar_2026/production_task_2026.py` 由 roslaunch 拉起约 6 秒后退出，退出码为 1；直接用 Melodic Python 2 导入复现为 `ImportError: cannot import name shortest_yaw_delta`。
- **原因**：本轮只同步了三套 `production_task_perception.py`，标准包 `ucar_2026` 的 `production_task_geometry.py` 仍是旧版；入口脚本已引用新接口，但依赖模块没有一起更新。国赛包的同名几何模块已是新版本，造成三套目录版本漂移。
- **处理**：对比本地/车端 SHA-256 和函数定义后确认问题定位，随后将新版几何模块同步到标准、省赛和额外三个车端入口；三套 Python 2 导入检查均通过。本次未重启任务、未发送运动指令，业务代码未修改。
- **预防**：生产任务部署必须按三套包的运行时依赖集合整体同步，并在每个实际入口目录执行 Python 2 导入检查；只核对单个入口脚本或感知模块不足以判定部署完成。
- **相关改动**：`2026-08-19-navigation-arrival-retry-continue.md`。

### 2026-08-19：OCR 连续对准在新鲜窗口内重复使用旧相机帧

- **现象**：移动 OCR 对准时连续多次 `horizontal_error_px` 基本不变，车辆仍持续发布旋转速度；本次日志前四次约 1 秒内保持 `-192px`。
- **原因**：ROS 图像抓取只检查最近帧不超过 `camera_frame_timeout=1.0s`，没有要求 `camera_sequence` 增加，连续请求可能保存同一帧。
- **修复**：三套任务脚本保存 ROS 图像前记录基线序号，只接受 `sequence > baseline_sequence` 的下一帧；新增回归用例并同步车端。
- **预防**：移动视觉闭环必须同时验证帧序号/时间戳新鲜度，不能仅凭“未超时”判定是新帧；车端动态单测若因导入条件跳过，必须明确改用 Python2 语法、哈希和安全启动解析验收。
- **相关改动**：`2026-08-19-ocr-next-frame-alignment.md`。

### 2026-08-19：IMU CRC16 日志关键词未被任务层放行

- **现象**：车端出现 `check crc16 faild(imu)` 时，任务同时输出 `PRODUCTION_TASK_ABORTED` 并停车。
- **原因**：任务层 `rosout_cb` 只把包含 `ahrs` 的 CRC16 当作告警；底盘 IMU 日志使用 `imu`，因此落入通用 `crc16` 致命标记。
- **修复**：三套任务脚本在通用结构故障判断前单独识别 `crc16 + imu`，输出限频 `PRODUCTION_IMU_CRC_IGNORED`；`imu sensor not active`、非有限 odom/TF 和其他结构故障仍保持中止。
- **预防**：任务层按底盘驱动的实际日志关键词建立回调回归用例；区分“单帧坏包告警”和“传感器持续失活”，不能用 `crc16` 总关键词直接覆盖两者。
- **相关改动**：`2026-08-19-imu-crc-warning.md`。

### 2026-08-19：同点旋转阈值小于导航到达容差

- **现象**：二维码面 232 到达误差 `0.068m` 已被任务层接受，但下一个同点负角度面 295 没有进入 odom 原地旋转，车辆停在扫描区。
- **原因**：普通到点使用 `arrival_tolerance=0.12m`，同点快捷路径却固定要求 `0.05m`；误差落在两个阈值之间时，同点目标被错误交给 `move_base`。
- **修复**：三套任务脚本让同点判断复用 `self.arrival_tolerance`，并加入 `0.068m` 回归测试。
- **预防**：同一导航状态的“已到达”和“同点旋转”必须共用到达契约；每次阈值调整都要覆盖临界现场误差。
- **相关改动**：`2026-08-19-qr-same-position-arrival-tolerance.md`。
