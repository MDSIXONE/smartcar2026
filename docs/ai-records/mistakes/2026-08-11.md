# 2026-08-11

### 2026-08-11：第二轮巡航 ALREADY_SERVED 死循环（第一轮预记录后转圈不前进）

- **现象**：第一轮巡航（找食品）在点 13 转圈时先识别到仿真类别「电子产品生产车间」
  （墙点 448），RECORDED 后因非目标类别不停车继续转圈；转圈中反复遇到同一墙点 448，
  `PRODUCTION_CATEGORY_ALREADY_SERVED` 每次命中，车反复停车对准同一位置，
  deadline 被每次候选处理延长，转圈永不完成、任务无限循环（与之前第二轮死循环
  同根同源，第一轮分支未被第一版修复覆盖）。
- **原因**：`handle_candidate` 对已记录类别仍执行完整 stop/align/range 流程且
  deadline 每次延长；第一轮 pre-record 后转圈应跳过已记录的非目标候选。
- **修复**：`handle_candidate` 新增 `PRODUCTION_CATEGORY_SKIP_RECORDED`
  分支——类别已记录且非当前目标时直接 return False（不停车、不延长 deadline），
  转圈继续前进。第一版修复（第二轮 target 覆盖）保留。
- **验证**：py_compile + 82 单测通过；20:02 任务完整跑通：食品停入 299 →
  电子产品停入 448 → SIMULATION_DONE → SUCCEEDED，点 13 电子产品被 SKIP
  后正常推进到点 16 找到食品。
- **预防**：已记录类别的候选不得再次触发停车对准；转圈 handler 对已满足条件的
  类别应尽快返回，避免 deadline 无限延长。

### 收臂完成后保留全局代价地图激光残影


- **现象**：夹取过程中物块被雷达短暂扫到并写入全局代价地图。物块随后随夹爪
  移动，新的激光射线被物块本身截断，旧的 map 坐标障碍格无法被射线清除，导致
  去工厂的路径被持续堵住。
- **原因**：上一轮修复只保证收臂完成后才启动导航，却未清除收臂阶段已经写入
  非滚动全局地图的动态障碍残影；已有 `clear_costmaps` 调用只位于导航超时重试
  路径，正常夹取成功后不会执行。
- **修复**：在两种夹取路径共用的收臂完成边界调用 `/move_base/clear_costmaps`，
  然后才切换 `laser_avoidance` 和发布携带模式；回归测试锁定“收臂 → 清图 →
  导航”的顺序。
- **预防**：动态物体从传感器视场进入车体携带包络时，必须在其处于传感器安全
  姿势后主动清除全局动态层，再启动依赖该地图的导航；不能假设后续命中会反向
  清除历史 map 坐标。

### QR 接收过滤误触发单面转圈

- **现象**：90°固定观察面收到非目标物品二维码后，任务立即开始转圈。
- **原因**：状态机将“二维码被目标过滤器拒绝”和“没有收到二维码”共用超时结果。
- **修复**：显式返回拒绝状态；拒绝后结束当前面并进入下一个固定观察面。
- **预防**：二维码扫描测试须区分无二维码、非目标二维码和目标二维码三种结果。

### OCR 分段停车不满足连续对准需求

- **现象**：OCR 居中视觉表现为每个小角度校正后停车，再重拍下一帧。
- **原因**：将“测距前必须停车”的安全约束错误扩大到每一帧 OCR 对准。
- **修复**：帧间持续发布角速度；仅 OCR 居中、空帧、超时或异常时停车确认。
- **预防**：为视觉控制明确划分连续控制阶段和必须静止的测量阶段，并为两者分别回归测试。

### SCP 多文件目标目录误投放

- **现象**：将四个不同子目录的文件以一次 `scp <files> ucar-mini:/home/ucar/ucar_ws/src/ucar_2026/` 传输，文件被落到包根目录而非 `scripts/`、`launch/`、`test/`。
- **原因**：多源 `scp` 的目标目录只保留各源文件的 basename，不会根据本地相对目录复建层级；随后首个远程巡检命令又在 PowerShell 双引号中让 Bash `$f` 被提前展开。
- **修复**：先按精确绝对路径核对四个误投文件，再删除这四个本次产生的副本；改为每个源文件指定完整远端目标路径，并用单引号包裹含 Bash 变量的 SSH 命令。
- **预防**：跨目录部署禁止使用单一多源 `scp` 目标目录；每个文件必须写明远端完整文件路径并逐项做 SHA-256 校验。PowerShell 调 SSH 时不得把 Bash `$变量` 放入双引号字符串。

### object.__new__ 单测缺少新增任务属性

- **现象**：车端 Python 2 回归在 81 项中报 6 个 `AttributeError: item_input_mode`；实车构造函数会设置该属性，但既有测试通过 `object.__new__` 绕过初始化。
- **原因**：主流程直接读取新参数属性，未保留测试替身和维护工具的历史 stdin 默认行为。
- **修复**：`run_mission` 通过 `getattr(self, "item_input_mode", "stdin")` 读取模式；真实 launch 仍默认 `voice`，仅未初始化对象退回 stdin。
- **预防**：给构造函数增加参数时，检查所有 `object.__new__`/mock 构造路径；核心入口应对可安全默认的新增配置使用兼容读取，并添加对应回归测试。

### 边界巡航 / middle target guard 适用范围不匹配

- **现象**：把补充路线的点 1 与内侧主路线一同传给 `load_middle_target_guard_points` 时，加载器要求不存在的端点 `(-2.500, 1.500)` 并拒绝任务配置。
- **原因**：四顶点目标守卫只为内侧生产格的中线端点设计；边界巡航格的外侧顶点没有相应的 `middle_line_endpoints` 编号。
- **修复**：仅为主路线构造四顶点守卫。补充路线显式禁用这一专用守卫，并继续通过通用安全门与 `move_base` 动态障碍层导航；守卫审计事件同时记录当前路线和下一目标。
- **预防**：将路线扩展到边界格前，先使用真实网格数据验证每个守卫映射；不要把“编号存在”当成“适用于中线守卫算法”。

### Catkin run_tests 子包目标被当作包名

- **现象**：车端执行 `catkin_make --pkg ucar_2026 run_tests_ucar_2026` 时，Catkin 0.7.29 将末尾字符串解析为包名并提示找不到后忽略；尝试把 `run_tests` 传给 `--make-args` 后，又因包内 Makefile 没有该目标而失败。
- **原因**：`run_tests` 是工作区顶层 CMake 的测试目标，不是 `--pkg` 子目录的 Make 目标，也不应放在 Catkin 的包选择位置。
- **修复**：保留现有白名单，在工作区根执行 `catkin_make -DCATKIN_ENABLE_TESTING=ON run_tests`；该次产生 94 tests、0 errors、0 failures、0 skipped。
- **预防**：车端 Catkin 测试先确认 Make 目标所在层级；不要从包限定构建命令推断同名的包级测试目标。操作文档使用工作区级 `catkin_make run_tests`。
