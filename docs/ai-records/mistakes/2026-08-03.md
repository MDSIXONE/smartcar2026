### 2026-08-03：首次 local footprint 实车任务在点 3 安全中止

- **现象**：车辆从固定起点通过有限里程计、两段 TF 和雷达安全门；先成功到达 52（误差 `0.031 m`）、完成三方向 QR（a/d/i）和相机启停。切至 `body_projection` 前往点 3 `(-1.250, 1.250)` 时，CymPlanner 连续报告 local raw 254 致命格 `(-1.455, 1.455~1.485)` 命中真实 footprint，并在候选 Twist 的 `0.225 s` 扫掠中被阻挡；全局重规划、清图和旋转恢复均无安全解，move_base status 4。任务立即零速并停止，车辆最后 map 位姿约 `(-1.314, 1.588)`，不再处于起点。
- **原因**：点 52 至点 3 的进入/转向几何使真实矩形车体接触中间区域的静态墙致命格。此前仅完成编译、单测和 launch 静态解析，未对这条实车进入路径做 local StaticLayer + 完整 footprint 的在线验证。
- **修复**：保持 raw 254/255 的失败关闭策略，不缩小 footprint、不放宽阈值、不强制穿过；发布零速，停止车端 launch 和 WSL Master，清除死亡 ROS 注册并保留日志与结果文件。
- **预防**：完整任务前，对每个模式切换后的首个目标先做静态 global plan 与 local footprint/转向扫掠验证；尤其检查中间墙角的 `52→3` 进入段。发生 status 4 后不得原地重启固定初值任务，必须先把车物理放回起点。

- **现象**：首次把 `check` 作为 `start_2026.sh` 的第一个参数，脚本将其解释为 Master IP 并安全拒绝；一次 WSL Master 检查遗漏 ROS 环境而找不到 `rosparam`；又把 ROS 2 风格的 `rosnode cleanup -y` 用于 Melodic，命令不支持该选项。停止 WSL Master 的组合检查因目标进程已退出返回非零。

- **预防**：实车脚本先读取 usage/首行参数定义；ROS CLI 选项以 Melodic `--help` 为准；停止后的 PID/进程检查允许“已不存在”作为成功状态，不应与关键停机操作共用退出码。

### 2026-08-03：本机 YAML 校验误用 Windows 默认 GBK

- **现象**：校验带中文 UTF-8 注释的 `ucar_cym_planner_params.yaml` 时，Python 3 以 Windows 默认 GBK 打开文件，抛出 `UnicodeDecodeError`；代码和配置均未被该检查改写。
- **原因**：校验命令省略了文本编码，错误地依赖终端默认编码。
- **修复**：后续 YAML 校验显式使用 `open(path, encoding='utf-8')`，再调用 `yaml.safe_load`。
- **预防**：Windows 本地对仓库 UTF-8 文本的 Python 读取必须显式编码；编码检查失败不能当作 YAML 语法失败，更不能据此修改配置。

### 2026-08-03：弹性局部路径首轮复核发现姿态和周期状态漏洞

- **现象**：初版局部带只插值位置、使用中心线朝向验证候选；相同 global plan 的周期性
  `setPlan()` 又会清空 active 带和 0.4 秒搜索计时。前者可能漏掉转弯扫角碰墙，后者会

  `0.30 rad/s` 上限。对 global plan 按弧长采样 7 点比较位置与切线，仅整段等价时保留
  active 带和搜索计时；显著改道才清除。
- **预防**：局部路径安全验证必须覆盖完整 `(x,y,yaw)` 连续扫掠和规划器跨周期状态；

### 2026-08-03：实车控制命令的 PowerShell 引号与死亡 ROS 注册

  `ip`、`pgrep` 解析错误；车端停止脚本已发布零速并退出进程，但 Master 一度保留死亡节点注册。
