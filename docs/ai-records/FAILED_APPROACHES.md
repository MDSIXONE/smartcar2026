# 已放弃方案

## 2026-08-14｜终点退出 2026.launch 后再启动 lane_proto

- **原方案**：生产任务成功后退出 required=true 的任务节点，使整个 `2026.launch` 释放底盘串口和 V4L2 相机；`handoff_lane.sh` 轮询资源可用后另启 `lane_proto.launch`。
- **停止原因**：用户观察到终点与巡线之间有明显停顿，明确要求不要再通过结束进程后重启巡线的方式交接。
- **证据**：`lane_proto` 原 launch 会独占第二个底盘驱动和 `/dev/ucar_video`，现有脚本必须等待 2026.launch 退出后才能启动。
- **替代方案**：主流程常驻唯一底盘驱动与 ROS 相机；lane_proto 待命订阅相机，在成功终点由明确的控制权话题切换，经单一速度仲裁节点接管底盘。

## 2026-08-11｜OCR 分段转动后重拍

- **原方案**：每次 OCR 像素误差都执行固定时长的小角度转动，转完先停车确认，再重拍下一帧。
- **停止原因**：用户明确要求对准阶段保持连贯转动；该方案的安全停车点使车辆呈现“动一下、停一下”。
- **证据**：`observe_wall` 在每次重拍之间同步调用 `rotate_in_place_for_yaw`，而该函数会在每段开始与结束均等待停车。
- **替代方案**：复用全圈 OCR 扫描的异步抓拍模式，在 OCR 未对准时持续发布受限角速度；首次达到像素容差后才发零速并确认停车，再进入激光测距。
