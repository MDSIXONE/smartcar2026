## PowerShell 通过 SSH 执行 Python2 校验时的嵌套引号

- 现象：首次远端 AST/XML 只读校验被 PowerShell 转义改写，车端 Python2 收到截断代码并报 `IndentationError`。
- 处理：上传文件和 SHA-256 未受影响；改为两个独立 SSH 只读命令，车端 `PY2_AST_OK`、`LAUNCH_XML_OK` 均通过。
- 预防：PowerShell→SSH→Python `-c` 不要多层嵌套转义；复杂校验拆分命令或改用 Base64 脚本。

- 症状：国赛任务日志显示 `sprint start point 70 stopped 0.056 m from target (limit 0.030 m)`，任务在 70→288 冲刺前 ABORT。
- 证据：任务代码只有在 `move_base` 返回 `GoalStatus.SUCCEEDED` 后才会生成这条 `stopped ... from target` 信息；日志目标为 `(2.250, 1.750)`，本地和车端共享网格哈希一致。

- 当前状态：未擅自放宽容差或修改 70 号点，等待根据现场定位稳定性决定修正定位/导航还是调整任务层阈值。

## 终点雷达两墙拟合状态码的含义

- 症状：终点视觉命中后持续出现 `两面墙不完整(x=2,y=0)`，车辆不继续调整，也不会播报“任务完成”。
- 原因：`corner_wall_fit()` 的 `x/y` 是四个方向候选墙的数量，不是激光点数量；`x=2,y=0` 表示 X 两侧均形成合格墙段，而 Y 两侧均未达到点数、跨度和残差条件。`step_corner_adjust()` 对拟合不完整直接返回零速度，最终会走雷达角落超时的 `ABORT` 路径。
- 预防：现场先检查 `/scan` 话题发布率、`frame_id`、车辆在终点触发瞬间的姿态，以及 `board_lidar_x=-0.11`、`board_lidar_yaw_deg=0.0` 安装标定；不要仅凭该计数直接放宽 `min_pts` 或强制播报。
- 关联变更：`CHANGE_LOG.md` 中的 2026-08-18 雷达到位后播报完成。

## ROS Melodic RecoveryBehavior 初始化接口

- 症状：车端首次编译恢复插件时报 `tf` 未声明、`initialize()` `override` 不匹配，插件类被判定为抽象类。
- 原因：车端 ROS Melodic 的 `nav_core::RecoveryBehavior` 接口是 `tf2_ros::Buffer* + global_costmap + local_costmap`，不是旧版单 costmap 的 `tf::TransformListener*` 接口。

## QR 同点负角度切换未锁定最短转向

- 症状：QR 旋转扫描从 `-90°` 切换到 `-135°` 时，车辆逆时针绕行一大圈。
- 原因：同点朝向目标直接交给 `move_base`，任务层没有显式计算目标角与当前角的最短有符号角差，也没有按 odom 累计实际转向进度。
- 修复：三套主流程对无规划且同点的朝向目标改用 odom 闭环；先归一化 `target-current`，再按符号发布原地角速度并验收实际进度。
- 预防：固定朝向同点旋转必须显式锁定最短角差并验证有符号 odom 进度，不能从目标角标签推断规划器一定会选择短弧。
- 关联变更：2026-08-19 QR 同点朝向切换最短旋转修复。

## 直接 roslaunch 未带车端 Master 生命周期

- 症状：停止旧任务后直接后台启动 `roslaunch`，进程存在但没有子节点；`rosnode list` 报 `Unable to communicate with master`。
- 原因：车端正式入口 `start_2026.sh` 负责计算 `ROS_MASTER_URI`、启动本机 `roscore`、再启动 `roslaunch`；直接启动没有恢复 Master 和对应环境。
- 预防：实车重启必须使用 `start_2026.sh <PC_IP> manual|mission`，启动后先检查 Master、`rosnode list` 和关键节点；不要只看 roslaunch PID。
- 关联变更：2026-08-19 导航到点偏差重试与继续流程。

## catkin 白名单缓存导致指定包构建无目标

- 症状：车端执行 `catkin_make --pkg cym_planner` 报 `No rule to make target 'cym_planner/all'`。
- 原因：工作空间 CMake 缓存仍保留 `CATKIN_WHITELIST_PACKAGES=usb_cam`；仅在当前 shell 中 `unset` 环境变量不会清除 CMake 缓存。
- 处理：显式传入 `-DCATKIN_WHITELIST_PACKAGES=` 强制重新配置后构建 `cym_planner`，完成后再恢复为 `usb_cam`。
- 预防：车端指定包构建前检查并显式设置 CMake 白名单；构建结束后恢复现场原有白名单。
