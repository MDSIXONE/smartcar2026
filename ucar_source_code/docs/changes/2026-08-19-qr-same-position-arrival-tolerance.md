# QR 同点旋转复用到达容差

日期：2026-08-19

## 问题

三套 2026 任务脚本的普通导航到点容差为 `0.12m`，但 `require_plan=false`
的同点旋转入口仍使用固定 `0.05m` 判断。实车在二维码面 232 到达时位置误差
为 `0.068m`，任务层已经接受到点，却跳过 odom 原地旋转并将同点负角度目标交给
`move_base`，车辆因此停在二维码扫描区不转。

## 修复

标准、省赛/额外、国赛三套 `production_task_2026.py` 将同点判断改为复用
`self.arrival_tolerance`。新增回归用例，固定当前位置与目标相差 `0.068m`，确认
仍调用 `rotate_in_place_to_yaw`，不会发送同点 `move_base` 目标。

## 验证与部署

- 本地三套几何回归共 `301` 项通过、`253` 项因本机缺少 ROS Python 模块跳过。
- 三套任务脚本本地语法检查通过；车端 Ubuntu 18.04 / Python2 AST 检查通过。
- 三套运行脚本和三套几何测试已同步到 `ucar-mini`，两端 SHA-256 一致。
