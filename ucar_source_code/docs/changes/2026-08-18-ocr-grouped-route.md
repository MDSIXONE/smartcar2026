# OCR 主路线四组前向/反向调度

## 目的

将三套 2026 主流程的生产 OCR 主路线调整为：

`12-13-14-15-16-17-18-19-29-28-27-26-25-24-23-22`

并将点位划分为四组：

- 第一组：`12, 13, 22, 23`
- 第二组：`14, 15, 24, 25`
- 第三组：`16, 17, 26, 27`
- 第四组：`18, 19, 28, 29`

## 行为

从点 3 完成二维码流程后，调度器按组前向运行。每组只先尝试一个尚未尝试的可达点；当前点完成旋转 OCR 后进入下一组。若当前点被动态目标守卫判定为不可达，才在本组继续尝试下一个点。完成第四组后，调度器从第四组向第一组反向扫描本轮仍为 `untried` 的点，直到类别找到或所有点均已扫描/忽略。

点状态仅在当前任务内维护：

- `untried`：尚未尝试，保留给反向补齐；
- `scanned`：已到达并完成 OCR；
- `ignored`：当前激光守卫命中，不再在本轮重复导航。

守卫只对当前目标点做实时判断，不提前判断远处同组点；原有外围兜底路线保留。额外任务使用非空 `ocr_route_profile` 时仍走快捷路线。

## 涉及文件

- 三套 `ucar_2026*` 的 `scripts/production_task_2026.py`：分组状态机、前向/反向游标、任务摘要；
- 三套 `scripts/production_task_geometry.py`：默认主路线、分组定义和配置校验；
- 三套 `launch/2026.launch`：同步路线参数；
- 三套 `test/test_production_task_geometry.py`：默认路线、分组和直线段回归；
- `docs/debug-rviz-observation.md`、`docs/operations.md`：参数和现场验证说明。

## 验证结果

- 三套几何测试通过：标准 `90` 项、国赛 `91` 项、额外 `105` 项（ROS 缺失测试按现有测试约定跳过）；
- 六个 Python 文件通过本机 `py_compile`；
- 三个 `2026.launch` 均通过 XML 解析；
- `git diff --check` 通过；
- 已按动态解析的 `ucar-mini` 地址同步 9 个运行时文件；两端 SHA-256 一致；车端 Ubuntu 18.04 / ROS Melodic Python2 语法 `6/6`、launch XML `3/3` 通过；
- 未在本机或车端启动主流程、导航或车辆运动，尚未替代车端构建和实车验证。

## 已知限制

分组调度只减少路线上的跨点往返，不改变单个点的 360° OCR、到达守卫、对准和停车流程。实车验证必须先确认 `/odom_raw` 有限、两个关键 TF 正常、车辆零速和激光数据新鲜，再从低速单组开始。
