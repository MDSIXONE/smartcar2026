# OCR 单点扫描补齐全部类别

日期：2026-08-20

## 现象

同一停车点能看到两个生产类别时，OCR 第一候选识别成功后立即停止旋转，日志中的
`PRODUCTION_OCR_TURN_COMPLETE` 进度只有 `0.032` 左右，后面的类别因此漏扫。

## 原因

`scan_production_point` 原来把 `target_category` 当成单点扫描的停止条件。第一轮任务虽然把真实类别和仿真类别一起传入了 `record_categories`，但只要真实目标类别先被记录，就设置 `_ocr_turn_stop_flag`，旋转函数随即提前返回。

## 修复

三套 2026 主流程统一改为：

- `record_categories` 非空时，只有其中所有类别都已记录才允许提前停止；
- 尚有类别未记录时继续当前 360° 扫描；
- 第二轮只寻找一个类别时，仍可在该类别记录后提前停止；
- 保留类别过滤、墙点去重、OCR 对准和当前姿态观察逻辑不变。

新增三套几何回归用例，验证第一候选不会置位停止标志，第二个所需类别记录后才置位。
