# 2026-08-20：QR 多结果队列与首次物品锁定

## 目的

裁判要求同一个二维码只以第一次成功解析出的物品为准；同时，摄像头同一帧可能出现多个二维码，不能由“最近一次结果”覆盖前面的结果。

## 改动

- `yolo2025/scripts/qrcode_scanner.py` 使用 OpenCV 多码接口返回一帧内的全部二维码；图像回调按检测顺序逐个发布，ROS 发布队列从 1 调整为 20，并继续复用同一 URL 的进程内 API 缓存。
- 标准、省赛/国赛、额外三套 `production_task_2026.py` 将 `/qr_api_result` 改为 FIFO 队列，逐个消费多个解析结果。
- 主流程按二维码 URL 保存第一次成功的物品；后续同 URL 即使 API 返回不同物品，也使用第一次结果并输出 `PRODUCTION_QR_FIRST_ITEM_LOCKED` 告警。
- 三套 `2026.launch` 将固定方向无结果等待上限统一为 `2.0s`；脚本的兼容默认值也同步为 `2.0s`。
- 三套几何回归新增“多个 API 结果不丢失 + 同 URL 首次物品不变”用例；二维码扫描器新增同帧多码发布和 OpenCV 多码解码用例。

- 三套 `test_production_task_geometry.py`：本机 ROS/Python2 依赖不可用，非 ROS 几何用例通过，任务层 QR 用例按既有条件跳过。

## 已知限制

- 同一任务进程内锁定 URL→首次物品；如果整个主流程重启，内存状态会清空，二维码扫描器也会重新建立进程内缓存。
- 不同二维码的 API 请求是异步的，多个不同二维码的消费顺序以 API 结果进入队列的顺序为准，不推断画面中的左右位置。
- 车端当前仅完成静态校验，尚未安全重启实际 `2026.launch` 或进行同帧多码实车验证；运行中的 Python2 节点不会热加载本次源码。
