# QR 分类超时响应串线修复（2026-08-18）

## 背景

二维码扫描阶段的 Spark 分类请求超时后，helper 进程仍可能处理旧请求。任务节点复用同一条 JSON 行管道，导致迟到响应被下一个二维码读取，出现类别错配并反复扫描。

## 修复计划

- 分类命令和响应增加 `request_id`，任务只接受当前请求的响应。
- 当前请求超时后终止 helper，下一次分类重新启动干净进程。
- 三套主流程把远程分类配置限制为单次 8 秒请求，不做串行重试；helper 仍可在远程失败后使用本地关键词表。
- 分类失败时释放已消费标记，允许有限扫描轮次重试；同一物品多次分类取最新结果。

## 验证

- 旧车端代码先通过新增回归复现：迟到响应用例因没有 `request_id` 失败，分类失败重试用例因二维码被提前标记失败。
- 修复后在车端加载 ROS Melodic 环境，三套包的两条定向回归均通过；标准包完整 90 项通过。
- 本地 9 个 Python 文件语法检查、3 个 launch XML 解析、helper request_id 协议冒烟通过；车端 Python2 语法检查和 helper 远端失败后本地分类协议检查通过。
- 三套主流程脚本、helper、launch 和测试已同步到 `192.168.8.231`；验证期间未启动任务、导航或运动进程。
- 国赛和额外包完整回归各有 1 个与本次 QR 改动无关的既有用例错误，分别位于交接状态测试和额外版 OCR 扫描测试。

## 已知限制

本轮不启动 ROS 主流程、不发送运动命令；真实讯飞接口延迟仍需车辆静止并通过安全门后现场观察。
