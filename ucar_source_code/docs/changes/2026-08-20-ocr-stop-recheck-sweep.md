# OCR 内墙 25cm 后退复核与尾部朝挡板停车

## 行为

首次 OCR 识别并完成雷达/地图墙点定位后，主流程使用 `ocr_stop_offset_m=0.25` 到达原先认定的墙内 25cm 停车点，车头朝向墙面。
随后使用 `ocr_recheck_backoff_m=0.25` 计算原停车点后方 25cm 的验证位，并通过普通导航直接到达该坐标（不发送倒车速度指令）；验证位从墙面法向 `-45°` 以受控角速度连续旋转到 `+45°`，旋转过程持续抓取 OCR 帧。
识别到与首次类别一致的结果后停止扫读并保留二次识别记录；完整范围内都未确认则任务报错，不继续播报或仿真。
确认成功后，无论是否需要纠正记录，主流程都回到认定停车区的原坐标，并将最终朝向设为墙面法向反向，即车尾朝向挡板，然后再执行播报或仿真。

这次复核针对的是“0.25 米偏差”，也就是吸附到 0.25 米网格时可能错一格；复核本身只确认类别与位置关系，不把无法从当前 OCR 帧计算出的纠正位置静默猜出来。

## 记录与验证

- 观察记录增加 `processing_stop_rechecks` 和 `processing_stop_recheck`，包含图像、文字、置信度、角度和类别。
- 观察记录增加 `processing_stop_final_parking_yaw`，明确最终尾部朝向挡板的停车姿态。
- 三套 launch 的 `ocr_stop_offset_m` 和 `ocr_recheck_backoff_m` 均统一为 `0.25m`。
- 本地验证：三套感知测试均 `14/14`；几何测试和车端 Python2 AST、launch XML、SHA-256 核对结果记录在提交说明中。
- 部署：已确认动态主机名 `ucar-mini` 解析到车端 `192.168.8.231`，同步前车端无 2026 主流程、`move_base`、`roscore` 或 `lidar_loc` 运行；同步后需逐文件核对 SHA-256，未自动启动任务。
