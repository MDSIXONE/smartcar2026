# 2026-08-18：扩展二维码扫描方向序列

## 目的

车辆到达二维码扫描中心点 52 后，将固定观察方向由
`180°→90°→-90°` 扩展为
`180°→90°→-90°→-135°→135°→45°`，以覆盖新增的三个对角方向；二维码收集、扫码结束后的点 3 路线、OCR、仿真联动和终点交接流程不变。

## 涉及文件

- `ucar_ws/src/ucar_2026/`
- `ucar_ws/src/ucar_2026_national/`
- `ucar_ws/src/ucar_2026_extra/`
- `docs/operations.md`

实现使用编号网格点 `[262, 232, 295, 61, 41, 43]` 计算中心点 52 的朝向，依次对应上述六个角度；车辆仍停留在点 52，不驶向这些边界/观察编号点。

## 验证结果

- 三套几何单测均新增并通过六方向方位角断言（本机使用 Python 3 运行）。
- 三套 `2026.launch` XML 解析通过，六个 QR 观察编号均存在于任务 JSON。
- 已按动态主机名同步到车端 `ucar-mini`：9 个运行时文件 SHA-256 与本地一致；车端 Python 2 编译检查通过；同步过程未启动 ROS 或车辆运动。
- ROS Melodic 车端动态 launch 与实车运动验证待执行；执行前须确认 `/odom_raw`、两段 TF、`/scan` 有限且稳定。

## 已知限制

- 扫码阶段每轮固定面数量从 3 个增加到 6 个；如果六面均无结果，既有旋转兜底逻辑和轮数限制仍按原实现执行，可能增加扫码耗时。
- `ucar_2026*/launch/production_task_2026.py` 中的同名遗留副本不是 CMake 安装入口，本次未修改或删除；正式节点来自各包 `scripts/production_task_2026.py`。
